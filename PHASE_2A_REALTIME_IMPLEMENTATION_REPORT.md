Event Architecture and Design Decisions### Shared Event Bus (`src/events.ts`)**Design Rationale:**- Single source of truth for all event publication- Supports multiple independent subscribers (SSE + in-process listeners)- Memory-efficient with cleanup functions for subscriptions- Typed event system prevents payload errors**Event Envelope Structure:**```typescriptinterface EventEnvelope {  id: string;                    // Unique identifier for Last-Event-ID support  timestamp: number;             // Unix timestamp for ordering  eventType: string;             // e.g., "task.created", "task.transitioned"  aggregateType: string;         // e.g., "task", "execution"  aggregateId: string;           // Entity ID (taskId, executionId)  payload: Record<string, unknown>; // Domain-specific data  schemaVersion: number;         // For compatibility tracking}```**Key Design Decisions:**1. **At-least-once delivery** - Events are published to all subscribers, may duplicate on reconnection2. **No event loss** - In-memory buffering ensures events reach all active subscribers3. **Schema versioning** - Enables future compatibility without breaking existing clients4. **Lightweight payloads** - Only essential data transmitted over SSE---## 2.
