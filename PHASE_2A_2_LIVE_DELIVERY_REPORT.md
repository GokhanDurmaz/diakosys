Replay-to-Live Synchronization Design### Problem StatementOriginal implementation:```typescript// Subscribeconst subscription = eventBus.subscribe((event) => {  reply.send(formatSSE(event));}, lastEventId);  // Replay from this point forward```**Race Condition:**1. Client sends Last-Event-ID (e.g., `evt_10`)2. Server replays events evt_11, evt_12, evt_133. **Meanwhile, new event evt_14 is published**4. Server subscribes to live events5. evt_14 may be missed or duplicated### Solution: Event BufferingImplemented a buffering mechanism that:1. Tracks when subscriber is still replaying2. Buffers new events ONLY during replay window3. Flushes buffer after replay completes4. Bounded memory usage (max 1000 buffered events per subscriber)### Implementation Details**Subscriber Structure:**```typescript{  callback: (event: SupportedEventType) => void;  sinceEventId: string | undefined;  buffer: SupportedEventType[];           // Events captured during replay  bufferMaxSize: number;                   // Bound at 1000  isReplaying: boolean;                     // Track replay state}```**Publish Logic:**```typescriptfor (const [id, { callback, buffer, bufferMaxSize, isReplaying }] of this.subscribers.entries()) {  try {    callback(envelope as SupportedEventType);  // Deliver immediately  } catch (err) {    console.error(`[EventBus] Error notifying subscriber ${id}:`, err);  }  // Buffer ONLY if subscriber is still replaying  const sub = this.subscribers.get(id);  if (sub && isReplaying && sub.buffer.length < bufferMaxSize) {    sub.buffer.push(envelope as SupportedEventType);  }}```**Subscribe Logic:**```typescript// Replay events if requested and availableconst replayEvents = this.getEventsSince(sinceEventId);if (replayEvents.length > 0) {  this.subscribers.get(id)!.isReplaying = true;  for (const event of replayEvents) {    try {      onEvent(event);    } catch (err) {      console.error("[EventBus] Error replaying event:", err);    }  }  // Flush buffer after replay completes - ensures no events were lost  this.flushBuffer(id);  this.subscribers.get(id)!.isReplaying = false;}```---## 3. Frontend Deduplication Implementation### Server-Side DeduplicationImplemented through intelligent buffering:- Events published during replay window are buffered- Buffer flushed after replay completes- Prevents duplicate delivery from server side### Client-Side Deduplication (Recommended)**Implementation Pattern:**```typescriptclass EventDeduplicator {  private seenEventIds = new Set<string>();  private maxSeenId: string | undefined;  shouldProcess(event: SupportedEventType): boolean {    const eventId = event.id;    // Ignore duplicates    if (this.seenEventIds.has(eventId)) {      return false;    }    // Only accept newer events (prevents stale updates)    if (this.maxSeenId && eventId < this.maxSeenId) {      return false;    }    // Mark as seen    this.seenEventIds.add(eventId);    this.maxSeenId = eventId;    return true;  }  clear() {    this.seenEventIds.clear();    this.maxSeenId = undefined;  }}```**Benefits:**- Prevents duplicate UI updates- Handles out-of-order events safely- Respects event ID ordering- Resets on connection recreation---## 5.
